# 操作学习架构边界

## 目标

操作学习采用 **Programming by Demonstration + 结构化工作流 + 逐步验证 + 受控视觉修复**。

它不是坐标宏，也不是把用户演示直接交给视觉模型自由重放。

## 强制状态链

```text
Intent
→ Recording
→ Compiling
→ ReadyForReview
→ Approved
→ Verified
```

原始演示轨迹只能生成草稿，不能直接进入执行状态。

## 分层

### 1. 演示层

负责显式录制、事件采集、动作前后快照和敏感信息脱敏。

不得：

- 持续监听用户操作；
- 在 Idle 状态扫描窗口或节点；
- 保存密码、验证码、支付确认内容；
- 直接生成可执行动作。

### 2. 编译与审核层

负责把演示轨迹整理为：

- 明确目标；
- 应用允许范围；
- 输入变量；
- 里程碑；
- 带多候选选择器的步骤；
- 每步前置与后置检查；
- 最终成功证据；
- 风险和恢复策略。

未经用户审核的草稿不得执行。

### 3. 确定性执行层

默认执行内核。只允许按已批准版本执行，并在每一步之后验证状态。

不得：

- 静默发明新步骤；
- 静默改变任务目标；
- 仅凭坐标执行；
- 在未授权应用中继续操作；
- 在缺少成功证据时宣布完成。

### 4. 视觉智能层

保留现有 `VisualLoopRunner`，禁止拆开或重写其稳定循环。

视觉循环只允许作为：

- 用户明确启用的高级模式；
- 确定性执行失败后的诊断能力；
- 用户再次同意后的受控修复能力。

学习工作流只能向视觉循环提供上下文，不得绕过现有安全校验和执行许可链直接下发动作。

## 选择器规则

目标必须使用选择器束，优先级为：

1. resource/view ID；
2. accessibility description；
3. 文本与控件角色；
4. 父级、同级和层级关系；
5. 相对锚点；
6. 视觉锚点；
7. 录制区域。

录制坐标只能作为低权重辅助线索。没有稳定候选选择器的步骤必须阻断审核。

## 验证规则

每个会改变状态的步骤必须定义后置检查。

每个工作流必须定义至少一个必需的最终成功证据。

动作执行成功不等于任务完成。

## 风险规则

- `Prohibited` 步骤永远不能执行；
- `High` 步骤必须每次确认；
- 敏感变量不能持久化实际值；
- 失败轨迹只能进入诊断区，不能自动污染正式版本；
- 路线修订必须生成候选版本并再次审核。

## 无障碍低负载约束

`ai_agent_accessibility_service.xml` 必须继续保持低负载配置。

无障碍运行时只允许在用户显式启动演示或执行任务时临时进入工作状态；结束、暂停、失败或停止后必须恢复 Idle。

禁止为了操作学习在 XML 中恢复持续事件监听。

## 数据边界

Room 数据库保存结构化工作流、版本和运行记录。

原始截图、节点树和事件轨迹必须使用独立的短期加密存储，并在编译、审核或过期后清理。不得把大图或原始敏感轨迹写入 Room 主表。

## 当前开发顺序

1. 冻结协议与校验器；
2. 完成草稿、审核和版本持久化；
3. 实现显式录制器与脱敏；
4. 实现轨迹编译器；
5. 实现确定性执行器；
6. 最后接入受控视觉修复。
